# @agent-core/tools-local

Optional Node-local capabilities for Agent Core applications: bounded search and reads, directory inspection, atomic text patching, process execution, image loading, and artifact access. Generic contracts, policy, authorization, observations, and registries live in `@agent-core/tools`.

Applications explicitly select from `list_directory`, `find_files`, `read_files`, `search_text`, `apply_patch`, `exec_command`, `write_stdin`, `stop_process`, `view_image`, and `read_artifact`.

Workspace file tools consume an adopted `WorkspaceFileRoot`, not an ambient path string. The root rejects aliases, multiply linked files, nested mounts, special files, `.git`, and application-private names. Reads and mutations stay relative to held directory authority even if another process replaces a pathname. `apply_patch` additionally requires a separately adopted `TextPatchJournal`; its directory must already exist, overwrite and delete plans bind both the source identity and its SHA-256 value, and the journal retains checksummed recovery receipts outside the generic workspace file namespace. `createLocalToolHost()` takes ownership of the application-adopted workspace root, artifact repository, and optional patch journal; it does not derive any authority from path strings. Close the host to release the transferred root and journal authority.

The handle-relative implementation currently requires Linux `/proc`. `WorkspaceFileRoot.adopt()` fails on platforms where the package cannot provide the same confinement contract. This is an explicit availability boundary, not a weaker portable mode.

`LocalCommandExecution` implements the shared `CommandExecution` contract for explicitly ambient applications and tests. It is not shell isolation: commands inherit the Agent Core process's file, network, and child-process authority. Its authenticated supervisor ledger provides a stable recovery identity and refuses unauthenticated or misowned process records. A persistent command holds the conservative `workspace/files` lease, so conflicting workspace tools wait until it exits or is stopped. Coding applications that require isolation must supply a sandbox-backed implementation instead of silently falling back to this local authority.
