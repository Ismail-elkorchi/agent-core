# `@agent-core/runtime`

Run orchestration, governed inference, original history, session-owned working state, conditional context windows, sessions, approvals, recovery, and finalization. Admission uses the accounting for the exact compiled model input, including content, tools, media, protocol state, and an explicit output reservation.

The root exports contracts and in-memory repositories. Import `@agent-core/runtime/node` for `JsonlSessionRepository` and `JsonlInferenceRepository`. Applications supply storage locations explicitly.

Application-owned working copies and publication policy do not belong to this package. Core records effect truth and finalizes runs; Coding Agent owns repository guidance and host-access policy, checks, diffs, and publication.

`EffectExecutionEvent` requires an observation for a settled state with a known outcome and forbids observations on other states. The event decoder verifies the observation's digest against the settlement before repository consumers use it.

See the repository's [context composition guide](../../docs/CONTEXT.md) for service boundaries and the public tool factories.

Work budgets are opt-in: applications may bound turns, tool calls, elapsed time, tokens, and cost. Defaults cover execution capacity, not task duration or a failure streak. Accounting continues without a configured budget. Context selection can omit settled exchanges within an active run while preserving original history, current input, and pending protocol obligations. Provider-native transforms may represent settled active exchanges when supported.

`AgentSession.close()` stops scheduling, interrupts the active run, and waits for its settlement. Queued submissions and suspended outcomes stay recorded for a new session instance; closing does not dispatch queued work or retry unknown effects.

Cancellation fences new work while allowing the owning driver to reconcile already-started provider outcomes and record their usage. A response committed during cancellation remains known; an unavailable outcome remains uncertain. Recording a result does not authorize consuming it to start more work after cancellation.

Model changes use `AgentSession.changeModel({ selection, profile, artifacts })` at an idle session boundary. Selected incompatible native state raises `ModelContinuationRequiredError`; an explicit user command may pass `continuation: 'fresh'`. The reset records the target model, a history cut, portable original source references together. Current working state remains session-owned. The next actual inference uses ordinary runtime request admission. Accepted input, answer content, complete tool exchanges, and supported original images remain available; native reasoning and opaque continuation state remain in original history. Pending work, uncertain effects, and unacknowledged result deliveries must be resolved first. A fresh continuation does not authorize replaying an uncertain request or terminating continuing resources.

`parseModelChangeRequest` decodes a flat model-selection command with an optional `continuation: 'fresh'`; the option is not a saved default. `recordedModelSelection` reads committed model selections and fresh resets without treating later carried source representations as another model choice.

Run control is constructed as `new AgentRunCoordinator(events, artifacts)` with the same durable artifact repository on every attachment and restart. `AgentRunRecords` stores protected, run-scoped tool sources, exact inputs, approvals, plans, effects, and settlements before a transition publishes their integrity-bound references. Transition creation and replay are asynchronous: pass the records instance to `createAgentRunStateTransition(previous, next, records)` and `applyAgentRunStateTransition(previous, transition, records)`. Obsolete inline tool transitions are rejected without altering stored data. Recovery requires the original artifacts; replacing them with an empty repository cannot authorize execution.

Operational collections contain outstanding work and release completed batches after synchronous recording or acknowledged native application. The outstanding-work admission bound is 256 provider requests or tool calls; accumulated historical payload volume is not a run limit. `pendingToolCalls(state)` and `assertToolTransitionBoundary(state)` query the durable driver's state directly. `AgentRunBudget` reads and updates that driver's counters and retains elapsed-time arithmetic without owning a phase machine. Inference invocations attributed with `runId` contribute their settled owner charges once, including transforms and native successors. Applications must retain the inference repository across continuation and attribute auxiliary run inference to the same run; continuing-owner budgets remain separate from run limits.

An ordinary generation failure before any answer, reasoning, or tool call is delivered ends that candidate attempt. A retryable provider error allows two bounded retries, each with fresh invocation admission. HTTP `Retry-After` guidance is recorded as an absolute retry deadline and respected alongside backoff; waiting remains cancellable and counts toward the run deadline. Explicit account spending-cap rejections are not retried. Earlier uncertain charges remain reserved and completed tools are never replayed. Permanent errors and exhausted retries end the run with a failure. A recorded failed attempt ends cleanly after process loss without restarting its retry allowance. Native execution, partially delivered output, unclassified failures, and process loss without a recorded settlement still require outcome reconciliation. `provider.attempt.failed` records unavailable generation output or rejected capacity; it does not assert that an uncertain provider charge was refunded.

Answers use answer-channel content exclusively. Reasoning summaries and interrupted reasoning remain in their original event/session fields; reasoning-only output has an absent answer.


Original observations and delivered model content have independent persistence identities. Audit `tool.ended.observation` is a `StoredToolObservation` with inline original data or a public artifact reference. `resolveToolObservation(source, artifacts)` verifies and reads it. Progress `tool.ended` carries the owned observation directly. `observation.record.created` and session observations carry exactly one delivered `modelContent` or `modelContentRef`; `resolveToolModelContent(record, artifacts)` resolves the original representation. Content is selected once before settlement and is reused by live delivery, recovery, native successors, and history. Formatter changes and UI expansion cannot regenerate older results. Old inline audit records and retired presentation envelopes are rejected.

`update_working_state` accepts the complete replacement text. The runtime binds session and branch scope, expected revision, and deduplication to the originating inference and durable tool invocation. Working state is optional generated understanding; it is not instructions or verification.

`context_transition` accepts `add`/`release` edits or an explicit `retain` replacement. It retains complete exchanges and protected inputs, and can atomically replace `workingState` after admission. No automatic summary or oldest-source eviction runs between turns. Source lookup uses an incremental, rebuildable substring index with bounded original reads, explicit coverage and stable cursors. Source snapshots share indexed ancestry rather than copying the branch on each append.

`continuation: 'fresh'` explicitly restarts native reasoning over selected originals while preserving the session, working state, effects, resources and budgets. `AgentSession.freshContinuation({profile})` exposes the same operation at idle boundaries; model switching shares its implementation. TUI context controls and RPC `context.fresh` expose it in both applications.

Native transforms remain a declared provider fallback for rejected capacity or required bound-prefix changes, and can be requested explicitly with `strategy: 'provider'`. Their inputs and successors pass governed admission; failure leaves the preceding window intact and cannot erase cost or unresolved exposure. With automatic context recovery enabled and an available context-transition capability, an ordinary request must also leave continuity room derived from compilation of the current bounded control request. A request may therefore enter recovery before overflowing. Mandatory native result delivery still admits its exact compiled capacity, but may consume discretionary continuity room: pending synchronous results must be delivered before a context transition is legal. The next discretionary boundary enforces the reserve again. Protocol-bound reasoning uses its original admitted prefix until a lawful native transform or explicit fresh continuation replaces it.

Automatic recovery uses the same runtime, inference service, owner accounting, and normal tool authorization. Its metadata-only control turns expose only context inspection, bounded history reads, and context transitions: no domain effects, final answers, working-state replacement, or implicit fresh continuation. At most four recovery requests are recorded per run, each reserving at most 1,024 output tokens and allowing at most two tool calls. Repeated unchanged actions stop; restart does not reset the allowance. Source and native-continuity conflicts remain durable suspensions when protected inputs, capabilities, authorization, or compiled capacity prevent progress. A candidate selection commits only after exact successor admission and revision checks.

Automatic-context tool presentations have an explicit 8 KiB text bound. A shortened presentation identifies itself as partial and references the persisted full selected presentation; original observations, coverage, execution facts, and call/result pairing remain unchanged. Storage failure does not silently shorten unavailable originals. Every actual successor and recovery request still passes admission; the continuity probe is not a guarantee about arbitrary future input. Recovery exchanges remain original history but do not become application conversation or native continuation.

## Session metadata index

`JsonlSessionRepository` persists its existing branch index as append-only, checksummed metadata checkpoints beside the session ledger (`.jsonl.index`). Successful source writes advance this index without rewriting historical metadata. Cold metadata capture validates and loads the index, without opening or decoding original transcript bodies. The existing in-memory branch index still has O(history metadata) cold initialization cost; `historyReadMetrics` exposes `metadataBytesRead` and `metadataRecordsRead` separately from source scanning and explicit body reads. Repeated metadata inspection on an unchanged repository does not reload the index.

Missing, incompatible, corrupt, or stale checkpoints fail explicitly. Use `rebuildHistoryIndex(session, { signal, onProgress })` for controlled recovery; it deliberately scans the original ledger and atomically replaces the metadata index only after a complete, validated scan. Cancellation preserves the previous committed index. A failed metadata write can occur after a source record commits; retry preserves that source identity, and metadata inspection remains blocked until recovery. Original source data is never deleted by index recovery.

When a mandatory native result itself exceeds actual capacity, the recorded result and
its delivery obligation remain intact in a clear context conflict. Source selection
cannot bypass that obligation; cancellation may be necessary when no lawful
continuation fits. This is not a promise of universal automatic resumability.
