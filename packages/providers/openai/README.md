# `@agent-core/provider-openai`

OpenAI Platform Responses API adapter for the provider-neutral contracts in `@agent-core/model`.

The highest-capability default is `gpt-5.6-sol`. Trusted built-ins cover the `gpt-5.6` Sol alias, Sol, Terra, Luna, GPT-5.5, and GPT-5.5 Pro; unknown models require a complete `OpenAIModelProfileDefinition`. Explicit definitions replace built-ins and are runtime-validated—partial profile merging is intentionally unsupported. GPT-5.6 profiles declare 1,050,000 context tokens, 922,000 maximum input tokens, 128,000 output tokens, efforts `low` through `max`, independent `standard|pro` modes, tiered component pricing, and the official `reasoning.mode` wire field. Current service tiers are `auto|default|flex|priority`; undocumented values fail before a request is sent.

Ordinary Platform requests are stateless: the adapter sends the full logical input with `store:false` and does not use `previous_response_id`. Bounded SSE/JSON framing is shared with the Codex adapter through `@agent-core/provider-openai-responses`, while authentication and product semantics remain separate.

## Typed protocol and modern execution

`compileRequest`, `completeCompiled` and `streamCompiled` bind accounting to an immutable provider body. Session variants retain transport state. The configured `defaultOutputTokens` (4096 by default) is sent as `max_output_tokens`; callers can supply an explicit cap. System/developer/user roles stay in causal input order. Required Responses reasoning blocks become exact provider context state; they are never rebuilt from `raw` or display summaries.

The exact Platform endpoint/model `https://api.openai.com/v1` + `gpt-6-astra` declares async direct function/custom tools and appended reasoning configuration. `transport: 'websocket'` enables native sessions; HTTP uses next-request delivery. Start governed native work with `session.streamCompiled(compiled, { signal, native: { admit } })`. `admit(dispatch)` must durably reserve and authorize the exact `dispatch.compiled` before returning. Missing admission rejects successor writes. Steering reserves bounded inherited parent output before its causative write; `generationDeliveryId` lets a subsequent required-result frame extend that same generation's reservation.

`continueNative({deliveryId,responseId,input,tools?})` starts independent activity at a completed response boundary while older async jobs remain pending. `deliverToolResults({deliveryId,responseId,results,sourceCalls})` needs no steering prerequisite. Each source binding retains its original `{responseId,catalogIdentity,toolCallId}`, even when the delivery parent or advertised catalog changes. Synchronous dependencies must all be supplied before continuation. New configuration and catalogs are compiled and accounted with the exact transport frame and retained context. Native steering accepts user contributions only.

`response_started` and `response_boundary` include `native` metadata: admitted input identity, generation/delivery IDs, the exact causal request/catalog, and structured pending/required call obligations. Runtime consumes each response boundary once for output, tools, and usage. The final `done` response is an **ordinary-consumer aggregate**, which includes old output/calls and aggregate usage; it is only stream closure for runtime and must never execute old calls or charge usage again.

Result delivery returns explicit submitted/acknowledged/applied/failed/uncertain states. `toolResultStatus`, `steeringStatus`, and `nativeDeliveryStatus` inspect retained evidence without sending. A uniquely correlated `response.created` proves application; it does not prove that successor inference completed or that a tool effect settled. Repeated identical delivery IDs query the same operation; changed input or reusing a call under another delivery rejects. Disconnects and uncertain sends are never retried. Known buffered provider evidence can reconcile application after a disconnect. No server polling or restart recovery capability is claimed: hosts persist delivery records, retain saved tool results, and suspend uncertain delivery when application cannot be proven.

`transformContext` calls `/responses/compact` and retains its **entire** returned canonical window as opaque state. Hosts govern transform invocation, resource reservation and activation through their context transition service. Custom endpoints do not inherit Astra modern capabilities by model-name match. Hosts own effect execution, durable delivery recovery, shared budgets, and cancellation policy. The adapter enforces transport cancellation and preserves uncertain delivery.

Verified protocol sources (2026-09-07): [Astra model](https://developers.openai.com/api/docs/models/gpt-6-astra), [async tools](https://developers.openai.com/api/docs/guides/async-tool-calling), [steering](https://developers.openai.com/api/docs/guides/steering), [compaction](https://developers.openai.com/api/docs/guides/compaction). Deterministic fixtures validate framing; no live account/model availability or quality measurement is claimed.

`countTokens: true` resolves opaque/media input cost through the bounded, cancellable `/responses/input_tokens` endpoint; `maxConcurrentCounts` defaults to two. The exact compiled input/tools/schema are counted before invocation, without a second generation call. Hosts include this admission I/O in their resource policy. Source: [input token counts](https://developers.openai.com/api/reference/cli/resources/responses/subresources/input_tokens/methods/count). Public Platform requests explicitly request encrypted reasoning output for stateless replay; the Codex subscription adapter retains its endpoint-specific default behavior.

Native transforms expose `compileContextTransform({transformId,request,signal?}, {outputReservation})` and `transformContextCompiled(transformId,compiled)`. Governed callers admit the exact `/responses/compact` model/input/instructions body and then send that owned body, with the original transform identity. Normal generation and transform compilations cannot be interchanged. The result carries the complete canonical returned window, safe usage, and replay state for `/responses`. `parseModelContextTransformResult` owns durable result boundaries. Compaction output uses a host reservation from the source request budget or compilation policy (standalone calls default to `defaultOutputTokens`); the compaction endpoint does not accept an enforced generation cap.

Compiled methods accept transport options separately from the immutable admitted object; `transformContextCompiled` accepts them as its third argument. The standalone compact window is replayed unchanged as the native input prefix. Current system/developer instructions supplied before that window in logical input are appended after the canonical prefix at their exact original roles; ordinary old conversation input before it is rejected.
