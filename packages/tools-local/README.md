# @agent-core/tools-local

Optional Node-local capabilities for Agent Core applications: bounded search and reads, directory inspection, atomic text patching, process execution, image loading, and artifact access. Generic contracts, policy, authorization, observations, and registries live in `@agent-core/tools`.

Applications explicitly select from `list_directory`, `find_files`, `read_files`, `search_text`, `edit_text`, `apply_patch`, `exec_command`, `write_stdin`, `stop_process`, `view_image`, and `read_artifact`.

File tools consume an adopted `RootedFileAuthority`, not an ambient path string. The authority rejects aliases, multiply linked files, nested mounts, special files, and Agent Core private entries. Applications must supply additional denied entries such as `.git` and their own private-state names. Reads and mutations stay relative to held directory authority even if another process replaces a pathname. `apply_patch` and `edit_text` use a separately adopted `TextPatchJournal`; its directory must already exist, write plans bind source identity and SHA-256, and checksummed receipts make exact transaction reconciliation idempotent. `createLocalToolHost()` takes ownership of the adopted root, artifact repository, optional patch journal, and optional application-supplied `CommandExecution`; it does not derive authority from path strings. When no command authority is supplied, an explicit process-ledger directory selects the ambient Node implementation. Close the host to release every transferred authority.

`read_files` validates the complete regular file as UTF-8 and reports its complete SHA-256 and newline convention even for a ranged result. `edit_text` accepts ordered, non-overlapping half-open ranges using one-based line and one-based Unicode-scalar positions. It checks the caller's complete-file SHA-256 and exact range preimages, preserves untouched text and the established newline convention, and commits every changed file in one journal transaction. Dry runs calculate the same plan without creating transaction state.

The handle-relative implementation currently requires Linux `/proc`. `RootedFileAuthority.adopt()` fails on platforms where the package cannot provide the same confinement contract. This is an explicit availability boundary, not a weaker portable mode.

`LocalCandidateWorkspace` materializes a complete source snapshot into private runtime state, persists exact checkpoints, derives bounded diffs, rolls text state back through a patch journal, and prepares journaled publication guarded by the original source digest. Binary, special-file, empty-directory, incomplete, stale-source, and unsupported metadata changes fail closed instead of being partially promoted.

`LocalCommandExecution` implements the shared `CommandExecution` contract for explicitly ambient applications and tests. It is not shell isolation: commands inherit the Agent Core process's file, network, and child-process authority. Its authenticated supervisor ledger provides a stable recovery identity and refuses unauthenticated or misowned process records. A persistent command holds the conservative `files` lease, so conflicting rooted-file tools wait until it exits or is stopped. Applications that require isolation must supply a sandbox-backed implementation instead of silently falling back to this local authority.
