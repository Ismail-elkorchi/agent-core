# `@agent-core/provider-openai-codex`

OpenAI Codex/ChatGPT subscription adapter for the provider-neutral contracts in `@agent-core/model`.

The default is `gpt-5.6`, with built-in Sol, Terra, and Luna profiles. `listModels()` discovers the authenticated account's model catalog; `describeModel()` discovers models without a built-in profile. Discovered profiles preserve the catalog's reasoning efforts and replace built-ins once the catalog is loaded. Complete `OpenAICodexModelProfileDefinition` overrides take precedence. Subscription capabilities come from this endpoint, including whether reasoning can be disabled; Platform pricing and `standard|pro` mode support are not inferred. Namespaced service tier accepts `default|priority`; obsolete aliases are rejected. HTTP full replay and WebSocket incremental continuation remain explicit strategies, and failed continuation resets conservatively. Both `complete()` and `stream()` use streaming transport; `complete()` collects its terminal response. A WebSocket session owns one active request through compilation, streaming, and fallback. Use separate sessions for parallel requests; overlapping use of one session rejects before dispatch.

Bounded Responses framing is shared with the Platform adapter; credentials, headers, model policy, and continuation behavior are not.

Catalog requests declare the adapter's supported Codex client compatibility version; the backend uses it to gate model visibility. Model identities and capabilities come from the account catalog rather than a release-specific allowlist. A selected model absent from a cached catalog triggers fresh discovery before it is reported unavailable; discovery failures remain distinct from account availability.

Typed protocol replay preserves native reasoning items and developer authority, with explicit endpoint/model/prefix compatibility. Compiled session methods reuse the admitted full body before applying the existing conservative exact-prefix WebSocket optimization. Changed instructions, catalogs or input prefixes retain full-replay fallback. Platform Astra steering and async-tool support are not inferred for the subscription endpoint.

This transport rejects a requested generation cap. `compileRequest(request, { outputReservation })` therefore receives an explicit host reservation policy, not a server-enforced cap. Core supplies its selected request-window reservation for both primary and auxiliary inference. Standalone compilation without a policy marks output reservation unknown; it cannot pass governed admission. Never reserve zero by default or equate encrypted state bytes with logical tokens.

The subscription transport supplies a stable `session-id` cache-affinity header on HTTP and WebSocket requests. Governed inference derives its scope from the existing inference owner; standalone provider sessions own an isolated default scope. This routing identity stays outside model content and compiled token accounting. Cache hits remain provider-reported facts, not guarantees inferred from shared prefixes.

Native compaction on the official subscription endpoint uses `codex.compaction`: an ordinary authenticated Responses stream with a final `compaction_trigger` input item, retaining the original tool declarations and instructions. It requires a completed response with exactly one opaque compaction item. That item becomes the transformed conversation; the runtime separately retains protected original input and current authority. This is distinct from the Platform `/responses/compact` canonical-window contract. Compiled transform identity, cancellation, affinity and usage pass through the existing governed inference path. Custom endpoint profiles do not inherit this capability; a complete explicit protocol profile controls declared support.

The protocol is checked against the [Codex remote compaction implementation](https://github.com/openai/codex/blob/cc7ba33/codex-rs/core/src/compact_remote_v2_attempt.rs). Transport fixtures qualify framing and failure handling, not live account/model behavior.
